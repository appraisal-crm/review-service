# review-service

Appraisal service for the Appraisal CRM. It creates an appraisal when a request
enters the appraisal stage, lets the appraiser record comparables, notes and the
market value, register the report file, and emits `report.ready` when done.

Part of a multi-repo system — see `request-service` for the reference layout and
conventions, and `CLAUDE.md` for the full charter.

> **Scope note:** the appraisal *calculation engine* is intentionally absent —
> the formulas are not formalized yet (risk R-001 in the BRD). `market_value`
> is entered manually and comparables are free-form JSONB until the Function
> Spec lands.

## Responsibilities

- **Consume** `request.status_changed` (topic `request.events`): a request entering
  `appraisal` creates an appraisal (status `in_progress`, unassigned).
- **Serve** the appraiser-facing API: view appraisals, take one over, enter
  comparables/notes/market value, register the report file, complete.
- **Produce** `report.ready` (topic `review.events`) through a transactional
  outbox so request-service can advance the request and notification-service can
  notify the client.

## Design

- **DB `review_db`** — `appraisals` (one per request, `request_id` UNIQUE),
  `comparables` (free-form JSONB), `appraisal_statuses` lookup, `outbox`.
- **Appraisal state machine:** `in_progress → completed` only. Completion is the
  single event-producing transition, guarded by a CAS on `status = 'in_progress'`.
  A completed appraisal is **frozen**: updates, comparables and report upload are
  rejected with 422.
- **Reports** live in S3 (Yandex Cloud); only the object key is stored. Uploads
  use a presigned URL — `internal/storage` is a stub until the S3 SDK is wired.
- **Idempotency** — the consumer checks `event_id` in Redis and marks it only
  *after* successful processing; a redelivered creation is absorbed by the
  `request_id` UNIQUE constraint.
- **Auth** — Keycloak JWT (JWKS, RS256 only, `exp` required). Role-only access:
  appraiser and admin see everything (per the BRD); clients never call this
  service directly.

## HTTP API

| Method | Path                                        | Roles            | Description                                    |
|--------|---------------------------------------------|------------------|------------------------------------------------|
| GET    | `/health`                                   | public           | Health check                                   |
| GET    | `/appraisals`                               | appraiser, admin | List (paginated, optional `?appraiser_id=`)    |
| GET    | `/appraisals/{id}`                          | appraiser, admin | Get one, with comparables                      |
| PATCH  | `/appraisals/{id}`                          | appraiser, admin | Set appraiser_id/notes/market_value            |
| POST   | `/appraisals/{id}/comparables`              | appraiser, admin | Add a comparable (free-form JSON)              |
| DELETE | `/appraisals/{id}/comparables/{comparableID}` | appraiser, admin | Delete a comparable                          |
| POST   | `/appraisals/{id}/report`                   | appraiser, admin | Register the report, get a presigned upload URL |
| POST   | `/appraisals/{id}/complete`                 | appraiser, admin | Complete → emits `report.ready`, freezes       |

Swagger UI at `/swagger/` (docs generated by `make generate`).

## Local development

```bash
# 1. Shared bus + auth (Kafka/Keycloak), once, from the repo root
docker compose -f ../infra/docker-compose.yml up -d

# 2. This service's data infra (Postgres :5436 + Redis :6383)
docker compose up -d

# 3. Migrate + run
cp .env.example .env
make migrate-up
make run
```

Or run everything (infra + migrations + service) in containers:

```bash
docker compose --profile app up -d --build   # needs ../infra up for Kafka/Keycloak
```
